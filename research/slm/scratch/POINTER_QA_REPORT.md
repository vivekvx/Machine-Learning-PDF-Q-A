# SLM-A scratch pointer QA: answer selection passes; sufficiency does not

**Decision (14 October 2026):** The trained neural pointer is a working **answerable-only, four-candidate synthetic technical QA reader**. It selected the exact source span for 218/240 questions from unseen validation documents. The separate support classifier failed its preregistered rejection gate. The combined answer/abstain system is **not validated**, the new sealed test set remains unopened, and there is no production RAG integration.

## Scope and reproducibility

- All text was generated by the local templates in [`pointer_qa/prepare.py`](pointer_qa/prepare.py). It contains non-medical technical facts, no external documents or pretrained assets, and no QASPER examples.
- Full documents and template families are disjoint: train has 300 documents and 1,200 answerable questions from four families; validation has 60 documents and 240 questions from a fifth family; the **sealed** partition has 60 documents and 240 questions from a sixth family. The test count comes from the frozen manifest; after generation its answer records were not read for training, checkpoint selection, or evaluation. Full entity names are disjoint; component words and some value vocabulary recur. Every passage has four facts and four distinct questions; every answer span and tokenizer offset was checked against source text.
- The 960-token byte BPE tokenizer was fitted only on training text. Encode/decode round trips, zero unknown-token behavior of byte fallback, document separation, source-span copying, and question sensitivity have focused tests. These rigid bracketed passages remain far simpler than academic PDFs.
- The native environment measured on this MacBook Air M2 with 8 GB unified memory: Python 3.14.6, MLX 0.32.3, mlx-metal 0.32.3, psutil 7.1.0. Configs, source checksums, sample order, run snapshots, learning curves, per-question predictions, checkpoint tensor/optimizer hashes, and the new hash ledger are under [`pointer_qa/`](pointer_qa/). The older `working_qa/ARTIFACT_HASHES.json` verifier still passes for all 70 files.

## Model and two bounded pointer attempts

The accepted v2 reader has **944,195 randomly initialized and trained parameters**: a 4-layer bidirectional MLX Transformer, width 128, four attention heads, learned token/position embeddings, RMS normalization, a trainable token-importance embedding, and a direct trainable token-alignment/context score. It ranks four *enumerated source spans* with cross-entropy. Source parsing locates bracketed spans; it never chooses the answer. This is an extractive pointer component, **not** the earlier generative decoder or a general-purpose language model. No NULL/`UNANSWERABLE` label occurs in its training or decoding.

The first, 1,009,153-parameter pooled-score pointer failed its tiny gate: 5/8 memorized after the 300-step cap, fixed-set NLL approximately 1.3863 (chance for four choices), and gradient norm dropped from 2.61 at step 1 to about 0.00003 at step 300. The code/offset tests did not reveal a target or masking defect. Saturation of the pooled scorer is a plausible mechanism, not independently proved. The one allowed correction replaced that scorer with direct token alignment while retaining the corpus, tokenizer, split IDs, seed, source-span objective, and safety limits. V2 passed 8/8 tiny examples at step 90 with distinct questions choosing distinct spans. The main v2 run then started from **fresh random weights**, not the tiny checkpoint.

| Run | Optimizer steps | Guarded wall time | Key result |
| --- | ---: | ---: | --- |
| v1 tiny, failed | 300 | 7.12 s | 5/8; no main run |
| v2 tiny, passed | 90 | 2.57 s | 8/8; exact checkpoint restoration |
| v2 main | 2,000 | 52.85 s | selected step 2,000; 108/120 fixed validation |
| separate support head | 1,200 | 21.46 s | gate failed; results below |

**Total: 3,590 optimizer steps and 84.0 seconds of guarded training wall time** across both pointer attempts and the separate classifier. The v2 main worker processed 326,888 candidate-pair input tokens at 10,229 input tokens/s (candidate duplication is included; this is not a unique-corpus-token count). Its fixed training NLL fell from 1.1650 to 0.2673 and fixed validation NLL from 1.1629 to 0.3733; fixed validation exact span accuracy rose from 46.7% to 90.0%. The selected checkpoint restored all 30 parameter tensors exactly with zero NLL difference.

The frozen v2 step-2,000 model was evaluated once on all 240 validation questions, separately from the 120-question fixed selection window.

| Exact source span | **218/240 = 90.8%** | at least 70% |
| Token F1 | 92.1% | diagnostic |

The metric field is weaker at **34/48 = 70.8%** exact, versus 93.8–97.4% for the other three fields. This remains a material failure mode. The selection path and every individual prediction, ID, span offset, latency, and score are in [`pointer_qa/v2/validation/`](pointer_qa/v2/validation/). No deterministic extractor was substituted for neural outputs. The new sealed test was not evaluated because the later sufficiency gate failed; therefore these validation figures are not a frozen-test generalization claim.

## Separately trained evidence-sufficiency checker

Only after the pointer validation gate passed, we generated balanced candidate-support records from the same **training and validation documents only**: 2,400 train records (1,200 supported / 1,200 unsupported) and 480 validation records (240 / 240). Each of wrong entity, wrong field, missing fact, and explicit correction/contradiction contributes equal positive/negative counts. Candidate offsets and support-index labels are programmatically checked. This is synthetic annotation, not independent human review.

The pointer weights were frozen. A **57,729-parameter** neural head learned from its question, full passage, candidate sentence/value, contextual interaction, and pointer-score features. It used 1,200 unique shuffled training records (611 supported / 589 unsupported), batch size 1, AdamW, and a train-only feature scaler. The validation documents were split before training into 20 for threshold calibration and 40 for checkpoint assessment. The selected step-1,200 checkpoint and optimizer state restored exactly; the pointer weight hash stayed unchanged. Its calibration-selected threshold is **0.70**.

| Assessment condition, distinct 40 documents | Supported accuracy | Unsupported rejection | Gate |
| --- | ---: | ---: | --- |
| Supplied labeled candidate spans, 320 balanced records | **129/160 = 80.6%** | **80/160 = 50.0%** | 70% / 70% — **fail** |
| Frozen pointer-selected spans, 200 distinct scenarios | **120/146 = 82.2%** | **32/54 = 59.3%** | diagnostic, also below rejection target |

For supplied candidates, 80 unsupported examples were falsely accepted and 31 supported examples falsely rejected. The 480-record full validation figures were 81.7% supported accuracy and 48.8% unsupported rejection. On pointer-selected spans, assessment had 22 false acceptances and 26 false rejections. Wrong-field and missing-fact cases remained weak. Validation BCE **worsened from 0.6983 initially to 0.9664** at the chosen checkpoint despite higher balanced accuracy, consistent with poor calibration/optimization stability; this is a diagnosis, not proof of its sole cause. The head is retained as a failed experimental artifact and is **not used by the demo**. Gold-proposed and pointer-proposed records and metrics are separate in [`pointer_qa/answerability/v1/`](pointer_qa/answerability/v1/).

## Resource measurements and safeguards

All training workers used the unchanged `scratch/run.py` preflight and a parent live watchdog with wall, pressure, available-memory, swap-growth, process-RSS, and disk aborts. No guard fired. The v2 main run's peak MLX allocation was **43.30 MB**, peak worker RSS **85.59 MB**, minimum available system memory **1.163 GB**, minimum reported free pressure **28%**, maximum swap-used growth **0 MB**, swap-out counter growth **5.13 MB**, and minimum disk headroom **57.17 GB**. The checker run's corresponding values were **25.40 MB**, **165.02 MB**, **1.206 GB**, **29%**, **29.36 MB**, **2.83 MB**, and **57.16 GB**. Swap-out counters are system-wide and cannot be wholly attributed to this process. These measurements demonstrate safety for these short bounded runs on this machine state, not an indefinite training budget.

## Integrity, limitations, and next gate

Fourteen focused tests passed for split isolation, balanced labels, offset/tokenizer alignment, question-sensitive scores, gradients and parameter updates, source-span copying, correction-position diversity, threshold accounting, and resource-guard trips. Training verified exact pointer and checker checkpoint restoration. The original `working_qa` ledger verified all 70 frozen files. The new hash ledger excludes the contents of `test.sealed.jsonl`; its SHA-256 was already frozen in the dataset manifest. No old RAG, QASPER, scratch-model, or earlier QA artifact was edited.

The demo is explicitly **answerable-only**, requires exactly four bracketed candidate values within the registered token budget, and provides no reliable refusal. It cannot yet accept ordinary unmarked PDF prose, unseen technical domains, or arbitrary missing/contradictory evidence. An answerability redesign must pass both 70% gates on validation before the combined system can be frozen and the sealed test opened exactly once. Do not tune against the sealed test. The prior deterministic template extractor's scores refer to a different dataset and are not substituted or presented as this neural model's result.

Verification and rebuild commands are in [`DEMO.md`](DEMO.md). No Qwen training, pretrained tokenizer/weights, hosted API, long unguarded training, deployment, or production RAG change occurred.
