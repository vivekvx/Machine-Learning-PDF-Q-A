Log both per arm and seed; use per-completion normalized loss where supported. The evidence-aware arm has fewer positive answer targets for answerable questions by design, so a difference from standard LoRA cannot be attributed uniquely to sufficiency awareness. ## Evidence labels and training targets

Labels describe the **supplied packed context**, independently of the original QASPER document-level answerability label. A context is **sufficient** only if its real source passages jointly contain every fact and relation needed for the supported answer and a traceable section/paragraph citation. **Partially sufficient** means relevant information is present but at least one indispensable answer-bearing fact or relation is absent; mere shortening, lexical overlap, or automatic redaction is not evidence of partial sufficiency. **Irrelevant** means real passages are supplied but none supports the requested answer, including accidental leakage checks. **Absent** means zero passages are supplied. All proposed labels require independent review; ambiguous or contradictory pairs remain quarantined.

An originally document-unanswerable question remains document-unanswerable even if a passage looks relevant; its target is `UNANSWERABLE` unless source adjudication overturns the original label in a new version. An answerable question with a failed retriever is **context-unanswerable**, while the document-level label stays answerable. Sufficient answerable contexts target a concise answer with a real citation. Partial, irrelevant, and absent contexts target exactly `UNANSWERABLE`. Store both labels. Do not fabricate passages, evidence IDs, page numbers, or human judgments. Any manually removed span for a partial case must retain original passage ID, exact removed span/offsets, transformation hash, and independent confirmation that the remaining context lacks the answer.

| Trained arm | Four planned exposures per question | Required supervision |
| --- | --- | --- |
| Standard supervised LoRA | Four repetitions of the same reviewed sufficient context for answerable questions; four repetitions of reviewed non-supporting contexts for document-unanswerable questions. | Answer/citation when supported; exact marker otherwise. |
| RAFT-style distractor LoRA | Same underlying questions with reviewed gold passage plus 0/1/2 real same-document distractors and prespecified beginning/middle/end gold positions; document-unanswerable items receive reviewed irrelevant/absent contexts. | Same answer target as standard when gold remains sufficient; exact marker for U. No chain of thought. |
| Evidence-sufficiency-aware LoRA | For answerable questions: one sufficient, one reviewed partial, one reviewed irrelevant, one absent context. For document-unanswerable questions: two reviewed irrelevant and two absent contexts. | Grounded answer only in sufficient condition; exact marker otherwise. |

The current `variant_plan.jsonl` records these intended exposures, with negative passage IDs and partial redactions **unset**. It is **not trainable JSONL**. Select distractors solely from permitted training source documents; inspect them for answer leakage and support before release. Randomize passage position according to the fixed seed and record the actual order. Preserve the full original annotations in the audit. No reference from validation or test may be used to construct training contexts.

## Output contract and separate abstention measures

Use the pinned Qwen chat template with thinking disabled and assistant-only completion labels. A response is either exactly `UNANSWERABLE` after outer whitespace trim, or a concise answer followed by at least one terminal, real `[section:i:paragraph:j]` citation corresponding to a supplied source passage. No prose refusal, markdown wrapper, page number, invented reference, or thinking trace satisfies the strict format. Record raw response, stop reason, parsed answer, citations, and errors separately. The user-facing prompt and parser must be fixed before future training and validation evaluation. The previously measured baseline is unchanged.

**Semantic abstention** asks whether the response declines to answer when the *supplied context* is independently judged insufficient; a prose refusal may count after blinded human coding even when it violates the strict format. Reviewers classify each response as `abstain`, `answer`, or `unclear` without seeing model arm or reference. **Exact marker compliance** requires `raw.strip() == "UNANSWERABLE"`; prose refusal fails this test. Report semantic abstention precision, recall, F1, and accuracy against reviewed context sufficiency, plus exact-marker precision/recall and strict answer-format compliance separately. Count `unclear` responses as non-abstentions and report them. For document-unanswerable and retrieval-miss cases, stratify by both original document answerability and context sufficiency. Never use a lexical refusal heuristic as an independent semantic judgment. The supplied-context ground truth for all 80 × 3 validation contexts requires review without model predictions; it is not currently established.

Also report answerable exact match/token F1, answer support and citation correctness by independent review, citation validity by mechanical ID check, invented citation rate, retrieval Recall@K/MRR/packed evidence coverage, truncation and malformed-output rates, latency, peak process/accelerator memory, and swap. Cluster uncertainty by document. Keep gold evidence, TF-IDF+FAISS, and MiniLM+FAISS as separate frozen retrieval conditions using the previous baseline's config hash `fe84cbcf58b6a9858a99fc2881a783810d629a29ad6b619dfc3453fae4e6d2db`. Gold evidence is diagnostic rather than deployable retrieval.

## Freeze and release gates

The fixed v1 train/validation ID files, source hashes, seed list, four-exposure schedule, final-checkpoint rule, answer contract, and evaluation conditions are the design freeze. A future independently reviewed, rights-cleared *materialization* requires a new versioned manifest with per-variant source IDs, context hashes, sufficiency adjudications, exact token counts, prompt and tokenizer hashes, cloud dependency lock, random order, training logs, and failure records. That release must pass tests for split isolation, source fidelity, leakage, truncation, assistant-only labels, and variant symmetry. Do not revise v1 in place. The official test split is opened once after all choices are locked, and any changes following test inspection are exploratory and require a fresh confirmatory set.

**GO for cloud training only if:** every retained paper's training rights are reviewed and documented; all 352 questions and all proposed context variants have independent evidence/answerability adjudication (including the one yes/no conflict); the matched cohort and token accounting are reproducible; each arm passes the same cloud preflight; and the versioned release manifests, tests, and blinded validation-context sufficiency labels are approved. **Present state: NO-GO.** This work performed no fine-tuning and establishes no performance improvement.
